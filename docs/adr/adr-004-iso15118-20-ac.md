# ADR-004: ISO 15118-20 AC in the same engine, chosen per session in the handshake

Date: 2026-11-23. Status: proposed (implementation in `feat/iso20`; to be
accepted after the tests against independent implementations, see "Open").
Context: ROADMAP item 1; EN ISO 15118-20:2022 is required for new and
renovated charging points in the EU from 1 January 2027 (Delegated Regulation
(EU) 2025/656).

## Context

The deployment answers ISO 15118-2 AC and the DIN 70121 SoC read for devices
of one operator. Vehicles on AC today mostly speak no ISO 15118 at all, some
ISO 15118-2, very few ISO 15118-20; new charging equipment has to support
ISO 15118-20 all the same. One deployment must therefore serve both versions,
and devices of two firmware generations, at the same time.

## Decision

1. **One engine, one state machine package.** `internal/secc` gets an
   ISO 15118-20 step (`iso20.go`) next to the ISO 15118-2 one; the state of a
   session says which protocol it runs (`State.Protocol`). The codec is
   libcbv2g's ISO 15118-20 part behind a second flat facade
   (`internal/exi/facade20.c`). No second engine, no second release line.
2. **The protocol is chosen per session in supportedAppProtocol.** Order:
   ISO 15118-20 AC, then ISO 15118-2, then DIN 70121 (the last only to read
   the SoC). ISO 15118-20 is offered only when `ISO20_ENABLED=true` and the
   device reported a TLS 1.3 connection to the EV (`Up.tls` with `open`):
   ISO 15118-20 runs over TLS 1.3 only, and a device that negotiated TLS 1.3
   carries the firmware for it. There is no separate capability flag. On a TCP
   or TLS 1.2 connection the same EV gets ISO 15118-2.
3. **The V2GTP payload type selects the schema.** ISO 15118-20 splits its
   messages over the CommonMessages (0x8002) and the AC (0x8003) schema; the
   device already forwards the payload type (`Up.pt`) and sends the answer
   with the one in `Down.pt`.
4. **Scope of this edition: AC with EIM.** Messages: SessionSetup,
   AuthorizationSetup, Authorization, ServiceDiscovery, ServiceDetail,
   ServiceSelection, AC_ChargeParameterDiscovery, ScheduleExchange,
   PowerDelivery (Start, Stop, Standby, ScheduleRenegotiation), AC_ChargeLoop,
   SessionStop. One energy transfer service, AC (ID 1), with two parameter
   sets: 1 Dynamic, 2 Scheduled (both MobilityNeedsMode 1, no pricing). Not in
   this edition: Plug & Charge, BPT (V2G), DC, AC-DER (Amendment 1), value-added
   services, service renegotiation, MeteringConfirmation. Their requests close
   the connection.
5. **Operator limits.** Dynamic: the limit is the EVSETargetActivePower of
   every loop answer (not above the EV's maximum); a new limit is a new
   Charging Loop pair. Scheduled: the schedule holds the station's power at
   the time of ScheduleExchange; when the limit changes, the loop answer
   carries EVSENotification ScheduleRenegotiation and the EV comes back to
   ScheduleExchange through the server.
6. **The EV's data in the operator's feed.** `ev.parameters` gets the target,
   maximum and minimum energy request (the target also as `e_amount_wh`, the
   field the activation pool reads for both versions), the EV's power limits,
   target and minimum SoC, the control mode; the SoC from the loop when the EV
   shows it.

## Consequences

- A deployment serves ISO 15118-2 and ISO 15118-20 vehicles and old and new
  device firmware together; switching ISO 15118-20 off is a setting.
- The device protocol changes only by the payload types and the pair kind of
  ADR-005; nothing changes for ISO 15118-2 devices.
- Real vehicles need a SECC certificate under a V2G root they trust: the
  service layer signs CertificateVerify of TLS 1.3 (secp521r1 or Ed448). Until
  a V2G PKI provider is chosen, ISO 15118-20 runs with test PKIs only.

## Open (against the text of the standard and independent implementations)

- Conditional requirements the schema does not show: MeterInfo in the loop
  answer when the EV sets MeterInfoRequested; requirements on the station's
  time stamp; whether Standby may be answered with OK (here) or must be
  WARNING_StandbyNotAllowed.
- Resuming a paused session on a new connection (OK_OldSessionJoined): the
  state is per connection today; a SessionSetupReq with an old session ID gets
  a new session.
- Tests against Josev (PyEvJosev, ISO 15118-20 AC, TLS 1.3), the EV side of
  EVerest and the EVerest reference station Evse15118D20; then the test harness
  scenarios and a mixed-fleet load run.
