# Security review of the first release

Review of the interfaces a deployment exposes, its defaults and the static
analysis findings, before the repository is opened (November 2026). The
negative tests listed in "To confirm under load" are run by the release's
functional test; their results are added here.

How to report a vulnerability: [SECURITY.md](../SECURITY.md).

## What a deployment exposes

| Port | Service | Who connects | Authentication |
|---|---|---|---|
| 8883 | broker (Mosquitto) | devices; the service layer | TLS 1.2+ with a client certificate of the deployment's CA; no passwords, no anonymous access |
| 80, 443 | gateway (Caddy) | operator systems; the host's health check | TLS (Let's Encrypt); `/v1` with an operator key, `/health` open |

Behind the operator's own TLS proxy (`compose.behind-proxy.yml`) the gateway
listens on `127.0.0.1:PUBLIC_PORT` only and 80/443 are not published.
Everything else (the broker's service listener 1883, Postgres, Valkey, the
API, the engines' health ports) is on the compose network only and is not
published in `docker-compose.yml`.

## Broker

| Check | Result |
|---|---|
| Device listener requires a client certificate (`require_certificate true`), the CN is the user name | yes (`mqtt/mosquitto.conf`) |
| Anonymous access refused on both listeners | yes |
| A device reaches its own subtree only (`pattern readwrite dev/%u/#`) | yes (`mqtt/mqtt-run.sh`) |
| CN `layer` (service layer) writes `registry/#` and nothing else | yes |
| CN `server` gets nothing on 8883: that account exists on 1883 only | yes |
| `server` and `layer` cannot be issued as device ids in `PKI_MODE=own` | yes (`pki/pki-init.sh` refuses them) |
| A blocked device keeps its TLS connection but can neither publish nor receive (deny before the pattern) | yes |
| Block list ids validated before they are written into the ACL (no ACL injection) | yes (`[a-z0-9-]` only) |
| Service listener 1883 not published | yes |

## Gateway and operator API

| Check | Result |
|---|---|
| Only `/v1/*` and `/health` are routed; anything else 404; Caddy admin API off | yes (`gateway/Caddyfile`) |
| `/docs` and `/openapi.json` of the API are not reachable from outside (not routed) | yes |
| TLS by default (Let's Encrypt for `SITE_ADDRESS`) | yes |
| Rate limit per operator key | yes, `RATE_LIMIT_PER_MIN` (600) |
| Rate limit per client address without a key | yes, `RATE_LIMIT_ANON_PER_MIN` (60) |
| Made-up keys do not each get a budget of their own | fixed in this review: requests with a key are also limited per client address (`RATE_LIMIT_KEYED_ADDR_PER_MIN`, 1200) |
| Behind the operator's proxy the limits see the real client, not the proxy | fixed in this review: `{client_ip}` with `TRUSTED_PROXIES` (none by default; `private_ranges` in `compose.behind-proxy.yml`) |
| Keys stored as SHA-256 only (generated keys: 256 bits of randomness; keys from `.env`: 16+ characters, checked at start); rights `read`, `control`, `debug` per key; revocation | yes (`api/app/auth.py`) |
| Every command is written to `audit_log` with the key's name | yes |
| `/health` reveals no internals beyond the state of the database and broker connections (exception class only) | yes |
| SQL built from constant fragments only, values as parameters | yes (bandit B608 and gosec G202 reviewed, see below) |

## Defaults

| Check | Result |
|---|---|
| No real passwords or keys in `.env.example` | yes |
| The deployment does not start with empty, example or short (< 16) passwords and keys | yes, `pki/preflight.sh` before the PKI, the broker and the database; tested in CI |
| `sslmode=disable` towards Postgres only on the compose network | yes; stated for operators in SECURITY.md |
| No private keys in the repository; test certificates are generated by the tests and fleetgen at run time | yes |
| Valkey without a password: compose network only, not published | accepted; an operator who publishes it must set one (`VALKEY_PASSWORD` is read by the engines) |

## Known vulnerabilities and licences

Checked by CI on every change and weekly (`.github/workflows/security.yml`):
govulncheck, pip-audit, trivy on every built image, go-licenses, pip-licenses.
Found and fixed in this review: 26 vulnerabilities of the Go 1.24 standard
library (toolchain moved to Go 1.26), Caddy 2.10 and its modules (2.11; golang.org/x/net raised to 0.62.0 in the build),
alpine 3.20 (3.24), base packages of the images. Dependabot did not watch the
Go module and the Dockerfiles (wrong folders); fixed.

Upstream images are reported, not failed: `postgres:16-alpine` carries `gosu`
built with an old Go; it only drops privileges at start and is not reachable
from the network.

## Static analysis

**bandit (API):** 6 × B608 (SQL from strings). Every query joins constant
column lists and conditions; values are parameters. Marked `# nosec B608` with
the reason.

**gosec (engine, relay, projector, fleetgen):**

| Rule | Where | Assessment |
|---|---|---|
| G114 health servers without timeouts | engine, relay, projector | fixed: `ReadHeaderTimeout` 5 s |
| G202 SQL concatenation | store, projector | constant conditions with `?`/`$n` placeholders, values as arguments: no injection |
| G115 integer conversions | worker index (`fnv` hash modulo the worker count), `itoa` of digits; fleetgen | bounded values: no overflow |
| G404 math/rand | engine: sampling of log lines; fleetgen: test timings | not security-relevant |
| G104 unchecked errors | `rows.Close()` in store | errors of the query are checked through `rows.Err()` |
| G402, G304, G306 | fleetgen only: `-insecure` flag, files named on the command line, report file mode | a test tool, run by its operator |

## Residual risks

- **Device ids in certificates of the service layer.** The broker takes the
  CN as the device id. A CN with `/` would map to a subtree of another device;
  `pki-init.sh` refuses such ids in `PKI_MODE=own`, in `PKI_MODE=layer` the
  layer's CA must issue valid ids only.
- **No certificate revocation list in `PKI_MODE=own`.** A device is cut off by
  the block list (its topics are denied at once); its certificate stays valid
  until it expires (`DEVICE_CERT_DAYS`, 365 by default). In `PKI_MODE=layer`
  certificates last 7 days.
- **Rate limits are per gateway process.** A deployment runs one gateway.

## To confirm under load (functional test, F4-a)

Negative tests against a running deployment: a certificate of another CA, an
expired certificate, CN `server`, a device writing another device's topic or
`registry/#`, a blocked device, a request without a key, with a revoked key,
with a key without the right, made-up keys over the per-address limit, the
API port and 1883 not reachable from outside.
